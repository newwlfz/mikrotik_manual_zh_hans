TR069-client 实现 CPE WAN 管理协议（CWMP）以进行远程设备管理，该协议由宽带论坛（BBF）标准化。CWMP 通过 IP 网络使用 HTTP(S) 与自动配置服务器（ACS）通信，ACS 可以监控、配置属性并更新远程设备的固件。它通常由 ISP 用于管理 CPE，但也可用于网络基础设施设备管理。

需要 tr069-client 软件包。

### 配置设置 {#configuration-settings}

**子菜单：** `/tr069-client`

TR069-client 菜单参数：

##### 可写设置 {#writable-settings}

客户端配置设置。

| 属性 | 描述 |
| :-- | :-- |
| **enabled** | 启用/禁用 CWMP 协议 |
| **acs-url** | ACS 的 URL。示例："[https://example.com:8080/path/](../getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)"、"[https://192.168.1.100/](https://192.168.1.100/)"  如果使用 HTTPS 访问 ACS，则必须在客户端的[证书存储](../authentication-authorization-accounting/certificates.md)中导入 Root CA，以验证 ACS 服务器证书。 |
| **username** | HTTP 认证用户名（由 CPE 用于“登录”到 ACS） |
| **password** *[敏感](../getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)* | HTTP 认证密码（由 CPE 用于“登录”到 ACS） |
| **periodic-inform-enabled** | 启用/禁用 CPE 周期性会话发起。定时器在每个成功会话后启动。当会话由周期性间隔启动时，Inform RPC 会包含 "2 PERIODIC" 事件。映射到 "Device.ManagementServer.PeriodicInformEnable" 参数 |
| **periodic-inform-interval** | 周期性 Inform 的定时器间隔。映射到 "Device.ManagementServer.PeriodicInformInterval" |
| **client-certificate** | 客户端/CPE 的证书，ACS 可将其用于额外认证 |

##### 只读设置 {#read-only-settings}

用于监控客户端状态的只读参数。

| 属性 | 描述 |
| :-- | :-- |
| **status** | CWMP 的信息状态。disabled - 协议已禁用，waiting-URL - 协议已启用，但未配置 ACS URL，running - CWMP 配置正确，并会在事件发生时与 ACS 通信 |
| **last-session-error** | 用户友好的错误描述，说明上一次会话为何未能成功完成 |
| **retry-count** | 连续未成功会话计数。如果 > 0，则 last-session-error 应指示错误。成功会话、禁用协议或重启后重置为 0 |

##### 命令 {#commands}

| 命令 | 描述 |
| :-- | :-- |
| **reset-tr069-config** | 完全重置并忘记 tr069-client 配置和状态（不影响其他 ROS 配置）。当 CWMP 进入无响应/挂起状态，并且需要在不重新安装 RouterOS 的情况下恢复时使用。 |

### CWMP 会话 {#cwmp-session}

CWMP 客户端通常会在不同事件（首次启动、重启、周期性间隔、远程请求、值变更等）发生时启动与 ACS 的通信（会话）。在每个会话中，CPE 和 ACS 可以调用 RPC 以在对方“执行”。CPE 始终以 Inform RPC 开始，其中包含连接原因、设备信息以及一些取决于配置的 Parameter 值。当 CPE 没有更多内容要说时，ACS 会执行其 RPC（大多数情况下是 Parameter 管理 RPC）。

### 参数和数据模型 {#parameters-and-data-models}

参数是简单的名称+值对，每个厂商可以决定其设备支持哪些参数。所有受支持参数的组合称为数据模型（DM）。BBF 定义了三个根数据模型（TR-098、TR-181:1、TR-181:2），厂商应基于这些模型提供其支持的参数。**RouterOS 数据模型基于 "TR-181 Issue 2 Amendment 11"**，这是最新的 DM，并由 BBF 推荐。

RouterOS TR069 客户端支持的[参数参考](pathname:///assets/tr069_parameters.html)

### 下载 RPC {#download-rpc}

#### RouterOS 更新（1 Firmware Upgrade Image） {#routeros-update-1-firmware-upgrade-image}

CWMP 标准规定，可以使用 Download RPC 并通过 FileType="1 Firmware Upgrade Image" 以及一个可下载文件的单个 URL（支持 HTTP 和 HTTPS）来更新 CPE 的固件。该标准还指出，下载的文件可以是任意类型，并且可以应用厂商特定的流程来完成固件更新。由于 MikroTik 的更新基于软件包（同时也是为了额外的灵活性），因此使用 XML 文件来描述固件升级/降级。目前，XML 配置支持提供多个文件 URL，这些文件将被下载，并像通过固件/软件包文件上传进行常规 RouterOS 更新一样应用。

以下是 RouterOS 捆绑软件包和 tr069-client 软件包更新的示例（不要忘记也更新 tr069-client 软件包）。应将 XML 文件放在某个 HTTP 服务器上，CPE 可访问该服务器进行下载。此外，可下载的 RouterOS 软件包文件也应以相同方式可访问（可以位于任意 HTTP 服务器上）。使用 ACS，执行 Download RPC，其 URL 指向 XML 文件（例如 "https://example.com/path/upgrade.xml"），内容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 将下载 XML，解析/验证其内容，从提供的 URL 下载文件并尝试升级。结果将通过 TransferComplete RPC 报告。

:::info
注意

始终以增量方式进行固件更新 - 首先，更新一台经过本地测试的设备，并确保 CWMP 通信在更新到新版本后恢复，且所需的 ROS 功能正常工作。其次，通过增量更新 CPE 分组来重复这些步骤。我们不建议一次性更新所有远程设备。

**警告：** 在生产环境中使用 HTTPS 进行固件管理
:::

#### 配置更改（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一个 Download RPC 可用于执行完整配置覆盖（按标准意图）或配置修改（当 URL 的文件名扩展名为 ".alter" 时）。

#### 修改配置 {#alter-configuration}

RouterOS 有许多配置属性，并非所有内容都能移植到 CWMP 参数。这就是 RouterOS 提供执行其强大脚本语言来配置任意属性的可能性的原因。可以使用 Download RPC FileType="3 Vendor Configuration File" 并搭配扩展名为 ".alter" 的可下载文件来执行配置修改（这实际上就是常规脚本执行）。借助此强大功能，可以配置通过 CWMP 参数无法使用的任意 ROS 属性。

#### 覆盖所有配置 {#overwrite-all-configurations}

可以使用 Download RPC FileType="3 Vendor Configuration File" 并搭配任意 URL 文件名（".alter" 扩展名除外）来执行完整的 ROS 配置覆盖。

**警告：** 提供的配置文件（脚本）必须足够“智能”，以便在重启后立即正确应用配置。当使用通过 Upload RPC 上传的配置文件时，这一点尤其重要，因为它只包含导出的值。以下是一些应手动添加的内容：

- 接口显示出来的[启动延迟](../getting-started/configuration-management/index.md#startup-delay)。
- 用户的隐藏密码。
- [证书](../authentication-authorization-accounting/certificates.md)。

#### RouterOS 默认配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此厂商特定的 FileType 允许更改在执行 `/system/reset-configuration` 命令时（或通过其他方式重置路由器配置时）执行的 RouterOS 默认配置脚本。

:::warning
注意

如果默认配置脚本被更改，则 `/system/default-configuration/print` 不会显示它，就像通过 Netinstall 工具更改该脚本时的情况一样。该命令将始终显示由 MikroTik 设置的默认脚本。

**警告：** 请谨慎使用，因为上传的脚本失败可能会导致设备无法操作和/或 ACS 无法访问
:::

### FactoryReset RPC {#factoryreset-rpc}

这是一个 CWMP 标准 RPC，用于执行 RouterOS 配置出厂重置。重置过程的执行方式与执行以下命令相同：

```
/system/reset-configuration skip-backup=yes

```

请注意，出厂默认配置可能因设备而异（参见[默认配置](../getting-started/configuration-management/default-configurations.md)），并且执行此命令会移除所有配置并执行内部存储的 default-configuration 脚本。

### 上传 RPC {#upload-rpc}

##### 上传当前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

其结果是上传到 ACS 的文件，与 RouterOS 中 `/export` 命令的输出相同

##### 上传日志文件（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

其结果是上传到 ACS 的文件，与 RouterOS 中 `/log/print` 命令的输出类似

##### 上传默认配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

其结果是上传到 ACS 的文件，其内容为当前设置的默认配置脚本；如果执行 `/system/reset-configuration` 命令，就会执行该脚本。它可能与使用 `/system/default-configuration/print` 返回的内容不同。

### 安全 {#security}

- HTTP 只应在安全/专用网络中测试初始设置时使用，因为中间人攻击者可以读取/更改配置参数。**在生产环境中，HTTPS 是必须的**。
- CWMP 的入站连接验证在设计上是安全的，因为 CPE 不会与除先前配置的 ACS 之外的任何其他设备通信。Connection Request 只会通知 CPE 与先前配置的 ACS 启动新连接 + 新会话。

### 让路由器准备好用于 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳实践指南展示了一个 RouterOS 初始设置示例，适用于需要使用自定义配置进行安全/预配置的出厂重置的情况，尤其是在使用 TR-069 时。当用户（或提供商在不知情的情况下）将设备误配置到不可逆转的状态时，这会很有用。然后可以使用 TR069 FactoryReset RPC、通过 RouterOS `/system/reset-configuration`，或使用路由器上的重置按钮来应用出厂重置配置。

##### 在 Netinstall 上覆盖出厂默认配置 {#overriding-factory-default-configurations-on-netinstall}

执行 Netinstall 时，可以调整 default-configuration 脚本以满足特定需求，并通过覆盖 MikroTik 的默认脚本来安装它。希望将 FactoryReset 作为备份的提供商会这样做，以便在某些无法解决的错误配置情况下使设备再次“可达”。在 TR-069 情况下，default-configuration 脚本至少应导入证书、设置 IP 层连通性、启用并配置 tr069-client、配置防火墙。之后，其他配置可以由 ACS 执行。

:::warning
在出厂重置时，所有证书也会被移除，因此如果重置后需要这些证书，则 default-configuration 脚本必须导入它们
:::
