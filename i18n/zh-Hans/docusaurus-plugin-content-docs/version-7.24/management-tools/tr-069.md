TR069-client 实现用于远程设备管理的 CPE WAN Management Protocol（CWMP），该协议由 Broadband Forum（BBF）标准化。CWMP 通过 IP 网络使用 HTTP(S) 与 Auto Configuration Server（ACS）通信，ACS 可以监控远程设备、配置属性并更新固件。它通常由 ISP 用于管理 CPE，也可用于网络基础设施设备管理。

需要 tr069-client 软件包。

### 配置设置 {#configuration-settings}

**子菜单：** `/tr069-client`

TR069-client 菜单参数：

##### 可写设置 {#writable-settings}

客户端配置设置。

| 属性 | 说明 |
| :-- | :-- |
| **enabled** | 启用或禁用 CWMP 协议 |
| **acs-url** | ACS 的 URL。示例："<a href="https://example.com:8080/path/" target="_blank" rel="noopener noreferrer">https://example.com:8080/path/</a>"、"<a href="https://192.168.1.100/" target="_blank" rel="noopener noreferrer">https://192.168.1.100/</a>" <br/> 如果使用 HTTPS 访问 ACS，则必须在客户端 <a href="/docs/authentication-authorization-accounting/certificates">证书存储</a> 中导入 Root CA，以验证 ACS 服务器证书。 |
| **username** | HTTP 身份验证用户名（CPE 用于“登录”ACS） |
| **password** *[敏感参数](/docs/getting-started/configuration-management/list-of-menus-with-sensitive-parameters)* | HTTP 身份验证密码（CPE 用于“登录”ACS） |
| **periodic-inform-enabled** | 启用或禁用 CPE 周期性会话发起。每次成功会话后启动计时器。当会话由周期间隔发起时，Inform RPC 包含“2 PERIODIC”事件。映射到“Device.ManagementServer.PeriodicInformEnable”参数 |
| **periodic-inform-interval** | 周期性 Inform 的计时器间隔。映射到“Device.ManagementServer.PeriodicInformInterval” |
| **client-certificate** | 客户端或 CPE 的证书，ACS 可使用该证书进行额外身份验证 |

##### 只读设置 {#read-only-settings}

用于监控客户端状态的只读参数。

| Property | Description |
| :-- | :-- |
| **status** | CWMP 的信息性状态。<ul><li>disabled - 协议已禁用，</li><li>waiting-URL - 协议已启用，但未配置 ACS URL，</li><li>running - CWMP 配置正确，将在事件发生时与 ACS 通信</li></ul> |
| **last-session-error** | 用户友好的错误描述，指示上一会话为何未成功完成 |
| **retry-count** | 连续失败的会话计数。如果 > 0，则 last-session-error 应指示错误。会话成功、协议禁用或重启后重置为 0 |

##### 命令 {#commands}

| Command | Description |
| :-- | :-- |
| **reset-tr069-config** | 完全重置并清除 tr069-client 配置和状态（不影响其他 ROS 配置）。当 CWMP 进入无响应或挂起状态，且需要在不重新安装 RouterOS 的情况下恢复时使用。 |

### CWMP 会话 {#cwmp-session}

CWMP 客户端通常会在不同事件发生时与 ACS 开始通信（会话）——首次启动、重启、周期间隔、远程请求、值更改等。在每个会话中，CPE 和 ACS 都可以调用 RPC 以在另一侧“执行”。CPE 始终以 Inform RPC 开始，其中包含连接原因、设备信息和根据配置确定的一些 Parameter 值。当 CPE 没有其他内容要发送时，ACS 会执行其 RPC（大多数情况下是 Parameter 管理 RPC）。

### 参数和数据模型 {#parameters-and-data-models}

参数是简单的“名称+值”对，每个厂商可以决定其设备支持哪些参数。所有支持的参数组合称为数据模型（DM）。BBF 定义了三个根数据模型（TR-098、TR-181:1、TR-181:2），厂商应基于这些模型确定其支持的参数。**RouterOS 数据模型基于“TR-181 Issue 2 Amendment 11”**，这是最新的 DM，也是 BBF 推荐的版本。

RouterOS TR069 客户端支持的[参数参考](pathname:///assets/tr069_parameters.html)

### 下载 RPC {#download-rpc}

#### RouterOS 更新（1 个固件升级镜像） {#routeros-update-1-firmware-upgrade-image}

CWMP 标准规定，可以使用 Download RPC 更新 CPE 固件，其中 FileType="1 Firmware Upgrade Image"，并提供一个可下载文件的 URL（支持 HTTP 和 HTTPS）。该标准还规定，下载的文件可以是任意类型，并可应用厂商特定流程完成固件更新。由于 MikroTik 的更新基于软件包（同时也为了提供额外灵活性），因此使用 XML 文件描述固件升级/降级。目前，XML 配置支持提供多个文件 URL，这些文件将被下载并应用，方式与通过固件/软件包文件上传进行常规 RouterOS 更新类似。

以下是 RouterOS bundle 软件包和 tr069-client 软件包更新的示例（不要忘记同时更新 tr069-client 软件包）。应将 XML 文件放置在某个 HTTP 服务器上，且 CPE 可以访问该服务器进行下载。此外，可下载的 RouterOS 软件包文件也应可通过相同方式访问（可以位于任意 HTTP 服务器上）。使用 ACS 执行 Download RPC，并将 URL 指向 XML 文件（例如“[https://example.com/path/upgrade.xml](https://example.com/path/upgrade.xml)”），文件内容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 将下载 XML，解析/验证其内容，从提供的 URL 下载文件并尝试升级。结果将通过 TransferComplete RPC 报告。

:::info
Note

始终以增量方式执行固件更新：首先更新一台经过本地测试的设备，并确认使用新版本后 CWMP 通信已恢复，且所需的 ROS 功能正常工作。其次，通过逐步更新 CPE 组来重复这些步骤。不建议一次更新所有远程设备。

**警告：** 在生产环境中使用 HTTPS 管理固件
:::

#### 配置变更（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一 Download RPC 可用于执行完整配置覆盖（符合标准预期）或配置变更（当 URL 的文件扩展名为“.alter”时）。

#### 变更配置 {#alter-configuration}

RouterOS 有大量配置属性，并非所有属性都可以映射到 CWMP Parameters。因此，RouterOS 提供了执行其强大脚本语言来配置任意属性的能力。配置变更（实际上是常规脚本执行）可通过 Download RPC FileType="3 Vendor Configuration File" 并使用扩展名为“.alter”的可下载文件执行。此功能非常强大，可用于配置 CWMP Parameters 中不可用的任意 ROS 属性。

#### 覆盖所有配置 {#overwrite-all-configurations}

完整 ROS 配置覆盖可通过 Download RPC FileType="3 Vendor Configuration File" 并使用任意 URL 文件名执行（扩展名为“.alter”的文件除外）。

**警告：** 提供的配置文件（脚本）必须足够“智能”，以便在重启后立即正确应用配置。使用通过 Upload RPC 上传的配置文件时，这一点尤其重要，因为此类文件仅包含导出的值。应手动添加的内容包括：

- [启动延迟](/docs/getting-started/configuration-management#startup-delay)，以等待接口出现。
- 用户的隐藏密码。
- [证书](/docs/authentication-authorization-accounting/certificates)。

#### RouterOS 默认配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此特定于厂商的 FileType 允许更改 RouterOS 默认配置脚本，该脚本会在执行 `/system/reset-configuration` 命令时执行（或在通过其他方式重置路由器配置时执行）。

:::warning
Note

如果更改默认配置脚本，则 `/system/default-configuration/print` 不会显示该脚本，这与通过 Netinstall 工具修改脚本的情况不同。该命令将始终显示由 MikroTik 设置的默认脚本。

**警告：** 请谨慎使用此功能。上传的脚本失败可能导致设备无法运行和/或无法通过 ACS 访问。
:::

### FactoryReset RPC

这是 CWMP 标准 RPC，用于执行 RouterOS 配置恢复出厂设置。重置过程与执行以下命令的方式相同：

```
/system/reset-configuration skip-backup=yes

```

请注意，默认出厂配置可能因设备而异（请参阅 [Default configurations](/docs/getting-started/configuration-management/default-configurations)），执行此命令会删除所有配置并执行内部存储的默认配置脚本。

### 上传 RPC {#upload-rpc}

##### 上传当前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

其结果是将文件上传到 ACS，内容与 RouterOS 中 `/export` 命令的输出相同

##### 上传日志文件（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

其结果是将文件上传到 ACS，内容类似于 RouterOS 中 `/log/print` 命令的输出

##### 上传默认配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

其结果是将文件上传到 ACS，文件内容为当前设置的默认配置脚本；执行 `/system/reset-configuration` 命令时将执行该脚本。它可能与使用 `/system/default-configuration/print` 返回的内容不同。

### Security

- HTTP 仅应在安全/私有网络中测试初始设置时使用，因为中间人攻击者可以读取/更改配置参数。**在生产环境中，必须使用 HTTPS**。
- CWMP 的传入连接验证在设计上是安全的，因为 CPE 不会与除先前配置的 ACS 之外的任何设备通信。Connection Request 仅向 CPE 发出信号，使其与先前配置的 ACS 建立新连接和新会话。

### 使路由器准备好使用 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳实践指南展示了 RouterOS 初始设置示例，适用于需要安全/预配置的恢复出厂设置并带有自定义配置的情况，尤其是在使用 TR-069 时。当用户（或提供商在不知情的情况下）将设备配置为不可恢复状态时，该方法可能很有用。此时可以通过 TR069 FactoryReset RPC、RouterOS `/system/reset-configuration` 或路由器上的重置按钮应用恢复出厂设置配置。

##### 在 Netinstall 中覆盖出厂默认配置 {#overriding-factory-default-configurations-on-netinstall}

执行 Netinstall 时，可以按需调整 default-configuration 脚本，并通过覆盖 MikroTik 的默认脚本进行安装。希望将 FactoryReset 作为备份，以便在出现无法解决的错误配置时让设备重新“可访问”的服务提供商应采用此方式。在 TR-069 场景中，default-configuration 脚本至少应导入证书、设置 IP 层连通性、启用并配置 tr069-client、配置防火墙。之后，其他配置可由 ACS 执行。

:::warning
恢复出厂设置时也会删除所有证书，因此如果重置后仍需要证书，default-configuration 脚本必须导入这些证书
:::
