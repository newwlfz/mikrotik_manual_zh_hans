TR069-client 实现用于远程设备管理的 CPE WAN Management Protocol（CWMP），该协议由 Broadband Forum（BBF）标准化。CWMP 通过 IP 网络使用 HTTP(S) 与 Auto Configuration Server（ACS）通信，ACS 可以监控远程设备、配置属性并更新固件。它通常由 ISP 用于管理 CPE，也可用于网络基础设施设备管理。

## 配置 {#configuration}

TR069-client 从 [`/tr069-client`](/docs/cli-reference/tr069-client) 菜单配置。

客户端配置包括可写设置，例如 **enabled**、**acs-url**、**username**、**password**、**periodic-inform-enabled**、**periodic-inform-interval** 和 **client-certificate**。只读设置（**status**、**last-session-error**、**retry-count**）用于监控客户端状态。[`/tr069-client/reset-tr069-config`](/docs/cli-reference/tr069-client/reset-tr069-config) 命令会完全重置并清除 tr069-client 的配置和状态（不影响其他 RouterOS 配置）。当 CWMP 进入无响应或挂起状态，且需要在不重新安装 RouterOS 的情况下恢复时，使用该命令。

有关可用参数的完整列表，请参阅 [CLI 参考](/docs/cli-reference/tr069-client)。

## CWMP 会话 {#cwmp-session}

CWMP 客户端通常会在不同事件下与 ACS 开始通信（会话），例如首次启动、重启、周期间隔、远程请求、值更改等。在每个会话中，CPE 和 ACS 都可以调用 RPC，以便在另一端“执行”。CPE 始终以 Inform RPC 开始，其中包含连接原因、设备信息以及根据配置确定的一些 Parameter 值。当 CPE 没有其他内容要发送时，ACS 会执行其 RPC（大多数情况下是 Parameter 管理 RPC）。

## 参数和数据模型 {#parameters-and-data-models}

Parameters 是简单的 name+value 对，每个厂商都可以决定其设备支持哪些 Parameters。所有受支持 Parameters 的组合称为 Data Model（DM）。BBF 定义了三个根 Data Model（TR-098、TR-181:1、TR-181:2），厂商应基于这些模型确定其支持的 Parameters。**RouterOS Data Model 基于“TR-181 Issue 2 Amendment 11”**。

RouterOS TR069 客户端支持的[参数参考](pathname:///assets/tr069_parameters.html)

## 下载 RPC {#download-rpc}

### RouterOS 更新（1 个固件升级镜像） {#routeros-update-1-firmware-upgrade-image}

CWMP 标准规定，可以使用 Download RPC 更新 CPE 固件，其中 FileType="1 Firmware Upgrade Image"，并提供一个可下载文件的 URL（支持 HTTP 和 HTTPS）。该标准还规定，下载的文件可以是任意类型，并可应用厂商特定流程完成固件更新。由于 MikroTik 的更新基于软件包（同时也为了提供额外灵活性），因此使用 XML 文件描述固件升级/降级。目前，XML 配置支持提供多个文件 URL，这些文件将被下载并应用，方式与通过固件/软件包文件上传进行常规 RouterOS 更新类似。

RouterOS bundle 软件包和 tr069-client 软件包更新的示例（确保同时更新 tr069-client 软件包）。将 XML 文件放在 CPE 可访问以下载的 HTTP 服务器上。可下载的 RouterOS 软件包文件必须以相同方式可访问（它们可以位于任意 HTTP 服务器上）。使用 ACS 执行 Download RPC，URL 指向 XML 文件（例如 "https://example.com/path/upgrade.xml"），其内容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 下载 XML，解析并验证其内容，从提供的 URL 下载文件，并尝试升级。结果通过 TransferComplete RPC 报告。

:::info
始终以增量方式进行固件更新：首先更新一台经过本地测试的设备，并确认 CWMP 通信在新版本中恢复，且所需的 RouterOS 功能正常工作。然后，通过增量更新 CPE 组重复这些步骤。不应一次性更新所有远程设备。

在生产环境中，固件管理应使用 HTTPS。
:::

### 配置变更（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一 Download RPC 可用于执行完整配置覆盖（符合标准预期）或配置变更（当 URL 的文件扩展名为“.alter”时）。

### 修改配置 {#alter-configuration}

RouterOS 有许多配置属性，并非所有属性都可以移植到 CWMP Parameters。因此，RouterOS 提供了执行其强大脚本语言来配置任意属性的能力。配置修改（即常规脚本执行）可以通过 Download RPC 使用 FileType="3 Vendor Configuration File" 和扩展名为 ".alter" 的可下载文件来执行。此功能可用于配置 CWMP Parameters 中不可用的任意 RouterOS 属性。

### 覆盖所有配置 {#overwrite-all-configurations}

完整 ROS 配置覆盖可通过 Download RPC FileType="3 Vendor Configuration File" 并使用任意 URL 文件名执行（扩展名为“.alter”的文件除外）。

:::warning
提供的配置文件（脚本）必须足够健壮，以便在重启后立即正确应用配置。使用通过 Upload RPC 上传的配置文件时尤其重要，因为此类文件仅包含导出的值。必须手动添加以下内容：

- [启动延迟](/docs/getting-started/configuration-management#startup-delay)，以等待接口出现。
- 用户的隐藏密码。
- [证书](/docs/authentication-authorization-accounting/certificates)。
:::

### RouterOS 默认配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此特定于厂商的 FileType 允许更改 RouterOS 默认配置脚本。执行 [`/system/reset-configuration`](/docs/cli-reference/system/reset-configuration) 命令时（或通过其他方式重置路由器配置时），将执行该脚本。

:::warning
如果更改默认配置脚本，[`/system/default-configuration/print`](/docs/cli-reference/system/default-configuration) 不会显示该脚本；使用 Netinstall 工具修改脚本时则会显示。该命令始终显示由 MikroTik 设置的默认脚本。

请谨慎使用。上传的脚本失败可能导致设备无法运行，或无法通过 ACS 访问。
:::

## FactoryReset RPC

这是 CWMP 标准 RPC，用于执行 RouterOS 配置恢复出厂设置。重置过程与执行以下命令的方式相同：

```
/system/reset-configuration skip-backup=yes

```

请注意，默认出厂配置可能因设备而异（请参阅 [Default configurations](/docs/7.24/getting-started/configuration-management/default-configurations)），执行此命令会删除所有配置并执行内部存储的默认配置脚本。

## 上传 RPC {#upload-rpc}

### 上传当前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

结果是上传到 ACS 的文件，与 RouterOS 中 `/export` 命令的输出相同。

### 上传日志文件（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

结果是上传到 ACS 的文件，类似于 RouterOS 中 [`/log/print`](/docs/cli-reference/log) 命令的输出。

### 上传默认配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

结果是上传到 ACS 的文件，其中包含当前默认配置脚本的内容；如果执行 `/system/reset-configuration` 命令，将执行该脚本。它可能与 `/system/default-configuration/print` 返回的内容不同。

## Security

- 仅在安全或私有网络中测试初始设置时使用 HTTP，因为中间人攻击者可以读取或更改配置参数。**在生产环境中，必须使用 HTTPS。**
- CWMP 的传入连接验证在设计上是安全的，因为 CPE 不会与除先前配置的 ACS 之外的任何设备通信。Connection Request 仅通知 CPE 与先前配置的 ACS 建立新连接和会话。

## 让路由器准备好使用 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳实践指南展示了一个 RouterOS 初始设置示例，适用于需要安全的、预配置的、带自定义配置的恢复出厂设置，尤其是在使用 TR-069 时。当设备被错误配置到不可恢复状态时（由用户或提供商无意中造成），该方法可能很有用。恢复出厂设置配置可以通过 TR069 FactoryReset RPC、RouterOS `/system/reset-configuration` 或路由器上的重置按钮应用。

### 在 Netinstall 中覆盖出厂默认配置 {#overriding-factory-default-configurations-on-netinstall}

执行 Netinstall 时，可以调整 default-configuration 脚本以满足特定需求，并通过覆盖 MikroTik 默认脚本来安装该脚本。如果提供商希望将 FactoryReset 作为备份手段，以便在配置错误无法解决后让设备重新可访问，则应进行此操作。在 TR-069 场景中，default-configuration 脚本至少应导入证书、设置 IP 层连通性、启用并配置 tr069-client，以及配置防火墙。之后，其他配置可由 ACS 执行。

:::warning
恢复出厂设置时，所有证书都会被删除，因此如果重置后仍需要证书，default-configuration 脚本必须导入这些证书。
:::
