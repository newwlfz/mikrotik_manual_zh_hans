TR069-client 实现了用于远程设备管理的 CPE WAN Management Protocol（CWMP），该协议由 Broadband Forum（BBF）标准化。CWMP 通过 IP 网络使用 HTTP(S) 与自动配置服务器（ACS）通信，ACS 可以监控、配置远程设备的属性并更新其固件。它通常由 ISP 用于管理 CPE，但也可用于网络基础设施设备管理。

## 配置 {#configuration}

TR069-client 通过 [`/tr069-client`](../cli-reference/tr069-client/index.md) 菜单进行配置。

客户端配置包括可写设置，例如 **enabled**、**acs-url**、**username**、**password**、**periodic-inform-enabled**、**periodic-inform-interval** 和 **client-certificate**。只读设置（**status**、**last-session-error**、**retry-count**）用于监控客户端状态。[`/tr069-client/reset-tr069-config`](../cli-reference/tr069-client/reset-tr069-config.md) 命令会完全重置并清除 tr069-client 配置和状态（不影响其他 RouterOS 配置）。当 CWMP 进入无响应或挂起状态，并且需要在不重新安装 RouterOS 的情况下恢复时，请使用此命令。

有关可用参数的完整列表，请参阅 [CLI 参考](../cli-reference/tr069-client/index.md)。

## CWMP 会话 {#cwmp-session}

CWMP 客户端通常在不同事件（首次启动、重启、周期间隔、远程请求、值变更等）下与 ACS 开始通信（会话）。在每个会话中，CPE 和 ACS 可以调用 RPC，让对方“执行”。CPE 始终以 Inform RPC 开始，该 RPC 包含连接原因、设备信息以及一些取决于配置的参数值。当 CPE 没有更多内容要发送时，ACS 执行其 RPC（这些大多数时候是参数管理 RPC）。

## 参数与数据模型 {#parameters-and-data-models}

参数是简单的名称+值对，每个厂商可以决定其设备支持哪些参数。所有受支持参数的组合称为数据模型（DM）。BBF 定义了三个根数据模型（TR-098、TR-181:1、TR-181:2），厂商应以其为基础来构建其支持的参数。**RouterOS 数据模型基于 "TR-181 Issue 2 Amendment 11"**。

RouterOS TR069 客户端支持的[参数参考](pathname:///assets/tr069_parameters.html)

## 下载 RPC {#download-rpc}

### RouterOS 更新（1 Firmware Upgrade Image） {#routeros-update-1-firmware-upgrade-image}

CWMP 标准规定，可以使用 Download RPC 并通过 FileType="1 Firmware Upgrade Image" 以及一个可下载文件的单个 URL（支持 HTTP 和 HTTPS）来更新 CPE 的固件。该标准还指出，下载的文件可以是任意类型，并且可以应用厂商特定的流程来完成固件更新。由于 MikroTik 的更新基于软件包（同时也是为了额外的灵活性），因此使用 XML 文件来描述固件升级/降级。目前，XML 配置支持提供多个文件 URL，这些文件将被下载，并像通过固件/软件包文件上传进行常规 RouterOS 更新一样应用。

以下是 RouterOS bundle 软件包和 tr069-client 软件包更新的示例（请确保也更新 tr069-client 软件包）。将 XML 文件放在 CPE 可访问的 HTTP 服务器上以供下载。可下载的 RouterOS 软件包文件必须以相同方式可访问（它们可以位于任意 HTTP 服务器上）。使用 ACS 执行 Download RPC，将 URL 指向该 XML 文件（例如 "https://example.com/path/upgrade.xml"），其内容如下：

```
<upgrade version="1" type="links">
   <config/>
   <links>
       <link>
          <url>https://example.com/routeros-mipsbe-X.Y.Z.npk</url>
       </link>
       <link>
          <url>https://example.com/tr069-client-X.Y.Z-mipsbe.npk</url>
       </link>
   </links>
</upgrade>

```

CPE 会下载该 XML，解析并验证其内容，从提供的 URL 下载文件，并尝试升级。结果通过 TransferComplete RPC 报告。

:::info
始终以增量方式进行固件更新——首先，更新一台经过本地测试的设备，并确保在新版本下恢复 CWMP 通信，且所需的 RouterOS 功能正常工作。然后，通过逐步更新 CPE 组来重复这些步骤。不应一次性更新所有远程设备。

在生产环境中使用 HTTPS 进行固件管理。
:::

### 配置更改（3 Vendor Configuration File） {#configuration-change-3-vendor-configuration-file}

同一个 Download RPC 可用于执行完整配置覆盖（按标准意图）或配置修改（当 URL 的文件名扩展名为 ".alter" 时）。

### 修改配置 {#alter-configuration}

RouterOS 有许多配置属性，并非所有内容都能映射到 CWMP 参数。这就是 RouterOS 提供执行其强大脚本语言的能力来配置任意属性的原因。配置更改（即常规脚本执行）可以使用 Download RPC 执行，其中 FileType="3 Vendor Configuration File"，且可下载文件的扩展名为 ".alter"。此功能可用于配置通过 CWMP 参数无法提供的任何 RouterOS 属性。

### 覆盖所有配置 {#overwrite-all-configurations}

可以使用 Download RPC FileType="3 Vendor Configuration File" 并搭配任意 URL 文件名（".alter" 扩展名除外）来执行完整的 ROS 配置覆盖。

:::warning
提供的配置文件（脚本）必须足够健壮，以便在重启后立即正确应用配置。当使用通过 Upload RPC 上传的配置文件时，这一点尤为重要，因为它只包含导出的值。必须手动添加的一些内容：

- [启动延迟](../getting-started/configuration-management/index.md#startup-delay)：接口出现所需的时间。
- Hidden passwords for users.
- [证书](../authentication-authorization-accounting/certificates.md).
:::

### RouterOS 默认配置更改（X MIKROTIK Factory Configuration File） {#routeros-default-configuration-change-x-mikrotik-factory-configuration-file}

此厂商特定的 FileType 允许更改 RouterOS 默认配置脚本；当执行 [`/system/reset-configuration`](../cli-reference/system/reset-configuration.md) 命令时（或通过其他方式重置路由器配置时），该脚本会被执行。

:::warning
如果更改了默认配置脚本，则 [`/system/default-configuration/print`](../cli-reference/system/default-configuration/index.md) 不会显示它，而使用 Netinstall 工具修改该脚本时则会显示。该命令将始终显示由 MikroTik 设置的默认脚本。

请谨慎使用此功能，因为上传的脚本失败可能会导致设备无法运行，或使 ACS 无法访问设备。
:::

## FactoryReset RPC {#factoryreset-rpc}

这是一个 CWMP 标准 RPC，用于执行 RouterOS 配置出厂重置。重置过程的执行方式与执行以下命令相同：

```
/system/reset-configuration skip-backup=yes

```

请注意，出厂默认配置可能因设备而异（参见[默认配置](../getting-started/configuration-management/default-configurations.md)），并且执行此命令会移除所有配置并执行内部存储的 default-configuration 脚本。

## 上传 RPC {#upload-rpc}

### 上传当前配置（1 Vendor Configuration File） {#upload-current-configuration-1-vendor-configuration-file}

结果是一个上传到 ACS 的文件，与 RouterOS 中 `/export` 命令的输出相同。

### 上传日志文件（2 Vendor Log File） {#upload-log-file-2-vendor-log-file}

结果是一个上传到 ACS 的文件，类似于 RouterOS 中 [`/log/print`](../cli-reference/log.md) 命令的输出。

### 上传默认配置（X MIKROTIK Factory Configuration File） {#upload-default-configuration-x-mikrotik-factory-configuration-file}

结果是一个上传到 ACS 的文件，其内容为当前默认配置脚本；如果执行 `/system/reset-configuration` 命令，该脚本将被执行。它可能与 `/system/default-configuration/print` 返回的内容不同。

## 安全性 {#security}

- 仅在安全或专用网络中测试初始设置时使用 HTTP，因为中间人攻击者可能读取或更改配置参数。**在生产环境中，必须使用 HTTPS。**
- CWMP 的传入连接验证在设计上是安全的，因为 CPE 不会与先前配置的 ACS 以外的任何设备通信。Connection Request 仅通知 CPE 与先前配置的 ACS 启动新连接和会话。

## 让路由器准备好用于 TR069 {#get-the-router-ready-for-use-with-tr069}

本最佳实践指南展示了一个 RouterOS 初始设置示例，适用于需要安全、预配置且带自定义配置的恢复出厂设置时，尤其是在使用 TR-069 时。当设备被（用户或提供商在不知情的情况下）错误配置到不可逆状态时，这可能很有用。恢复出厂设置配置可以使用 TR069 FactoryReset RPC、通过 RouterOS `/system/reset-configuration`，或使用路由器上的复位按钮来应用。

### 在 Netinstall 上覆盖出厂默认配置 {#overriding-factory-default-configurations-on-netinstall}

执行 Netinstall 时，可以调整默认配置脚本以满足特定需求，并通过覆盖 MikroTik 的默认脚本来安装。希望将 FactoryReset 作为后备手段、以便在出现无法解决的错误配置后让设备重新可达的提供商应这样做。在 TR-069 场景下，默认配置脚本至少应导入证书、设置 IP 层连通性、启用并配置 tr069-client，以及配置防火墙。之后，其他配置可以由 ACS 执行。

:::warning
恢复出厂设置时，所有证书都会被移除，因此如果重置后需要这些证书，默认配置脚本必须导入它们。
:::
